# Настройки и расположение данных

Пользователь меняет тему, горячие клавиши, шрифты, параметры терминала и соединений в рамках административной политики. В обычном режиме могут настраиваться состав панели, quick commands и прокси соединения.

Admin policy принудительно применяет управляемые значения при чтении/сохранении/старте, не только скрывает форму. К ним относятся sync endpoint, AI endpoint, MCP, обновления, отчёты и некоторые startup/proxy-настройки. Правка локальной БД не является поддерживаемым обходом.

Точная таблица ключей и переменных: [ADMIN-VS-USER.md](../ADMIN-VS-USER.md). Значения по умолчанию: [DEFAULTS.md](../DEFAULTS.md). Исторические QA-заметки в этих документах не отменяют [ограничения версий](Versions.md).

## Данные

Обычный Desktop использует каталог `anubis`: Windows `%APPDATA%\anubis`, macOS `~/Library/Application Support/anubis`, Linux `~/.config/anubis`. `DATA_PATH` меняет путь в поддерживающем его режиме; это не команда миграции и не универсальный override защищённого machine host.

При первом запуске пустого нового каталога предусмотрено копирование совместимого старого `electerm`-профиля. Старое имя оставлено ради совместимости; исходные данные не перемещаются и не удаляются. Наличие реальных данных препятствует миграции; ошибка копирования не должна открывать пустую БД как будто всё успешно.

Machine host хранит SYSTEM отдельно от пользовательского профиля и использует защищённую native-конфигурацию. Не направляйте GUI-кэши на профиль worker и не переносите ключи между Windows accounts.

## Страницы модулей Scarab и Aegis

В Arsenal доступны отдельные страницы **Anubis Scarab — DLL Scanner** и
**Anubis Aegis — CVE Scanner**. Это изменение исходников интерфейса, а не
обновление установленной версии 5.7.44 или её установщика.

Обе страницы занимают основную рабочую область справа от бокового меню,
а не выезжающую панель настроек. WEB использует тот же общий renderer.
Настройки находятся сверху, статус и результаты — ниже на той же странице.
Существующие терминальные сессии остаются смонтированными и доступны после
возврата через **Back to workspace** или перехода к инструменту рабочей области.
Страницы наследуют текущую тему приложения, стили форм, кнопок и таблиц;
отдельного preview-интерфейса или собственной палитры у них нет.

Scarab содержит путь к модулю, папку сканирования, фильтры архитектуры, подписи,
кандидатов и прав записи, а также цветовые пороги DLL/EXE по образцу Robber.
Размер EXE задаётся в KB. Черновик настроек сохраняется в localStorage текущего
браузера; путь по умолчанию — `C:\ProgramData\Anubis\modules\scarab`. Этот путь
не подтверждает наличие установленного модуля. Запуск, отмена и экспорт пока
недоступны: их предстоит подключить через Broker вместе с хранением результатов.
Страница не запускает процессы и не создаёт демонстрационные результаты.

Aegis использует локальный сервис-посредник `aegis-service`: интерфейс не
запускает процессы напрямую. При первом запуске установки сервис записывает
пути `C:\ProgramData\Modules\cve-scanner-js` и
`C:\ProgramData\Modules\cve-scanner-py` в `cve-scanner/settings.json` каталога
данных этого runtime. Кнопка **Save module paths** сохраняет их на целевом ПК,
не в localStorage оператора. Изменения из приложения и Control Center используют
одну конфигурацию и revision check: устаревшее сохранение отклоняется.

Интерфейс и диагностические сообщения Aegis отображаются на английском.
Неподтверждённые keyword/CPE-кандидаты по умолчанию скрыты; их можно включить
через **Include unverified keyword/CPE candidates**. Счётчики отдельно
показывают version-matched advisories и unverified candidates; ни один из этих
типов не означает подтверждённую эксплуатацию. Проверка применимости патчей
Windows не реализована. Недоступный KEV показывается как **Unavailable**,
а не как отсутствие CVE в каталоге.

JS-модуль передаёт флаг NVD `isVulnerable` без значения. При недоступности
основного CISA endpoint оба сканера используют официальный GitHub-каталог
`cisagov/kev-data`; ошибки обоих источников остаются видимыми.
Python-модуль выбирает ОС из текущего инвентаря, а не константу Windows Server.
Его JSON-отчёт сохраняет связанные продукты, помечает результаты кандидатами
и сообщает об ограничении числа записей. Старые текстовые отчёты без
привязки продуктов требуют повторного сканирования обновлённым модулем.
Выбор другого Windows runtime (SYSTEM/пользователь) не объединяет их данные.

В `https://control.anubis.locker` используется отдельная страница Aegis с выбором
подключённого browser-agent конкретной установки. Она передаёт подписанные
команды `aegis.settings/configure/start/latest/get/cancel` с ролью operator.
Management UUID и browser-agent ID не взаимозаменяемы; совпадение имён ПК
не создаёт связи. Старые клиенты без этих команд требуют обновления.

Перед запуском требуется согласие на запросы OSV/NVD и загрузку CISA KEV.
Полный инвентарь не отправляется: наружу идут идентификаторы/версии продуктов.
JS запускается через Node/Electron-as-Node как `run.js run --job <directory>`,
с `input.json`, `job.json`, `progress.jsonl` и `result.json`; `data` результата
проверяется по схеме модуля. Python запускается своим `python.exe`: сначала
`windows_system_inventory.py --output <fresh-file>`, затем
`windows_inventory_cve_audit.py` в отдельной рабочей папке с этим инвентарём.
Каталоги должны находиться внутри локального административного allowlist
`C:\ProgramData\Modules`; центральная панель не принимает произвольные shell-команды.

Сервис ожидает оба результата, объединяет CVE по идентификатору, сохраняет
High/Critical либо CVSS >= 7, источники и отметку KEV. Последний результат и
архивы по run ID хранятся в `cve-scanner/latest.json` и `cve-scanner/history`.
Сбой одного сканера не скрывает второй; отмена, таймаут и неполное покрытие
отображаются явно. После перезапуска незавершённое задание становится interrupted,
а не запускается снова. Через сеть результаты читаются страницами до 100 находок.

Фильтры отображения: CISA KEV, CWE из полученных отчётов, High/Critical и
минимальный CVSS. Без ограничений видны все сохранённые высокорисковые находки.
Фильтрация не удаляет исходные результаты. Python использует keyword/CPE-поиск,
а не проверку точной установленной версии и патчей; такие записи помечены
кандидатами, покрытие — partial. Высокий CVSS не доказывает уязвимость этого ПК.

В Desktop Browse открывает локальный выбор папки. В WEB путь целевого ПК вводится
вручную: выбор папки на машине оператора не является выбором папки целевого ПК.
Черновики Scarab остаются локальными; это не меняет целевую конфигурацию Aegis.
